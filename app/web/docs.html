完整接口参考

CONVENTIONS

通用请求约定

所有接口使用当前站点作为 Base URL。解析接口上传文件，管理接口提交 JSON，响应最外层始终为 JSON。

认证AuthorizationBearer <API_KEY>

除 /health 和 /v1/info 外均必填。

请求追踪X-Request-IDdemo-request-001

可选，允许字母、数字及 ._:-，最长 128 字符；响应头会原样返回。

文件上传Content-Typemultipart/form-data

由 HTTP 客户端自动生成 boundary，不要手工固定该请求头。

JSON 配置Content-Typeapplication/json

仅 PUT /v1/admin/config 使用。

默认文件上限50 MB
默认 PDF 页数50 页
默认 OCR DPI200
最大 OCR DPI300
默认结果保留24 小时
安全提示

API Key 不应放入 URL、前端源码或业务日志。生产调用建议主动传入唯一的 X-Request-ID 便于端到端排查。

OUTPUT FORMATS

output_formats 返回格式

参数值是逗号分隔字符串，可选择一种或多种格式。选择格式不会改变 HTTP Content-Type；结果始终放在 JSON 响应的 outputs 对象内。

响应字段outputs.markdown
{
  "outputs": {
    "markdown": "# 项目方案\n\n正文内容……"
  }
}
值字段类型说明
textstring

提取后的纯文本；OCR 页面之间使用空行分隔。

jsonobject

结构化结果。RapidOCR 返回 pages[]、页面尺寸、文本与 blocks[]。

markdownstring

Markdown 文本。OCR 路径会按 ## Page N 分页。

htmlstring

HTML 片段。OCR 路径按 <section data-page> 组织。

AUTO ROUTING

engine=auto 的实际逻辑

auto 是自动路由策略，不是独立引擎。PDF 会先由 PyMuPDF 检测文本层，再选择 OpenDataLoader、RapidOCR 或组合解析。

PNG / JPEG / WebP / TIFFRapidOCR

图片必须执行 OCR；ocr=never 或显式选择 OpenDataLoader 会返回 422。

text_pdfOpenDataLoader

所有页面文本长度均达到阈值，保留文档结构。

scanned_pdfRapidOCR

所有页面均低于文本阈值，先按 DPI 渲染，再逐页 OCR。

mixed_pdf组合解析

OpenDataLoader 处理结构，低文本页由 RapidOCR 补齐。

ocr=auto

按文档检测结果自动决定。

ocr=always

PDF 强制使用 RapidOCR。

ocr=never

PDF 强制使用 OpenDataLoader。

自动降级

自动模式下 OpenDataLoader 失败会降级到 RapidOCR。

用于负载均衡、容器探活和部署验收。status=degraded 表示至少一个解析组件不可用，但接口本身仍返回 HTTP 200。

POST/v1/parse
Bearer API Key

同步解析文档

上传文件并等待解析完成，成功返回 ParseResponse。适合图片和短 PDF；长文档建议使用异步任务。

请求参数 · multipart/form-data

字段类型 / 默认值说明与示例
file 必填File

PDF、PNG、JPEG、WebP、TIFF。示例：@resume.pdf。

engineenum · auto

auto、opendataloader、rapidocr。

output_formatsCSV string · text,json

text,json,markdown,html 的任意非空组合。

ocrenum · auto

auto、always、never。

dpiinteger · 服务默认值

OCR 渲染 DPI，必须在 72 与当前 max_dpi 之间。

include_bboxboolean · true

是否在 OCR JSON 的每个文字块中返回 bbox；置信度始终返回。

include_imagesboolean · false

设为 true 后把内嵌图片、OCR 页面图或原始图片上传到阿里云 OSS，并返回 assets。

请求 · cURL
curl -X POST /v1/parse \
  -H "Authorization: Bearer <API_KEY>" \
  -H "X-Request-ID: parse-scan-001" \
  -F "file=@scan.pdf" \
  -F "engine=auto" \
  -F "output_formats=text,json,markdown" \
  -F "ocr=auto" \
  -F "dpi=200" \
  -F "include_bbox=true" \
  -F "include_images=true"

响应字段类型说明
request_idstring

请求追踪 ID，与响应头 X-Request-ID 一致。

filenamestring

经过安全处理后的原文件名。

enginestring

最终实际使用的引擎，不一定等于请求中的 auto。

detected_typestring

image、text_pdf、scanned_pdf、mixed_pdf。

outputsobject

只包含 output_formats 请求的格式。

assetsarray

图片资源列表。未开启图片输出时为空数组；kind 为 embedded_image、page_image 或 source_image。

assets[].urlstring

OSS 图片 URL。公共域名模式下地址本身不签名且 expires_at=null；对象仍会随结果保留期限被定时删除。私有桶模式返回有时效的签名地址。

meta.page_countinteger

文档总页数；图片固定为 1。

meta.duration_msinteger

服务端解析耗时，单位毫秒。

POST/v1/jobs
Bearer API Key · HTTP 202

创建异步解析任务

请求字段与同步解析完全相同。文件入队后立即返回 job_id，Worker 在后台处理。

请求参数

file、engine、output_formats、ocr、dpi、include_bbox、include_images 的定义与 同步解析一致。

请求 · cURL
curl -X POST /v1/jobs \
  -H "Authorization: Bearer <API_KEY>" \
  -F "file=@large-document.pdf" \
  -F "engine=auto" \
  -F "output_formats=markdown,json" \
  -F "ocr=auto" \
  -F "dpi=200" \
  -F "include_bbox=true" \
  -F "include_images=true"
响应 · 202
{
  "job_id": "job_7f4c1f0c8a6e4f85a8c2…",
  "status": "queued",
  "progress": {
    "current_page": 0,
    "total_pages": 0
  },
  "error": null
}
GET/v1/jobs/{job_id}
Bearer API Key

查询任务状态

客户端应使用创建任务返回的 job_id 轮询。建议从 1–2 秒间隔开始并逐步退避。

路径参数类型说明
job_id 必填string

创建任务时返回的 ID，格式为 job_...。

queued

已入队，等待 Worker。

processing

正在解析，进度字段持续更新。

succeeded

成功，可请求结果接口。

failed

失败，查看响应内 error。

expired

任务或结果超过保留期限。

请求
curl -H "Authorization: Bearer <API_KEY>" \
  /v1/jobs/job_7f4c1f0c8a6e4f85a8c2
响应 · 200
{
  "job_id": "job_7f4c1f0c8a6e4f85a8c2…",
  "status": "processing",
  "progress": {
    "current_page": 8,
    "total_pages": 24
  },
  "error": null
}

Bearer API Key

获取异步任务结果

仅当任务状态为 succeeded 时返回 HTTP 200 和完整 ParseResponse。未完成返回 409，结果文件过期返回 410。

请求
curl -H "Authorization: Bearer <API_KEY>" \
  /v1/jobs/job_7f4c1f0c8a6e4f85a8c2/result
成功响应 · 200
{
  "request_id": "job_7f4c1f0c8a6e4f85a8c2…",

  "engine": "opendataloader",
  "detected_type": "text_pdf",

    "markdown": "# 文档标题\n\n正文……",

  },
  "meta": { "page_count": 24, "duration_ms": 6840 }

ERROR MODEL

错误响应与处理建议

所有服务端业务错误都使用相同结构。调用方应同时记录 HTTP 状态、error.code 和 request_id。

错误响应示例 · 422
{
  "error": {
    "code": "INVALID_ARGUMENT",
    "message": "Invalid output formats: ['xml']",
    "request_id": "demo-request-001"
  }
}
4xx

修正认证、文件或参数后再请求，不应直接重试。

409

任务未完成，继续按退避间隔查询状态。

5xx

可进行有限次数指数退避重试，并保留 request_id。

HTTP错误码触发条件建议
401UNAUTHORIZED

API Key 缺失或无效。

检查 Authorization 请求头。
404JOB_NOT_FOUND

任务不存在或已被清理。

停止轮询并重新创建任务。
409JOB_NOT_READY

任务状态尚未 succeeded。

继续查询任务状态。
410JOB_RESULT_EXPIRED

结果文件已经过期。

重新提交原文件。
413FILE_TOO_LARGE

上传文件超过大小限制。

压缩、拆分或调整配置。
413PDF_TOO_MANY_PAGES

PDF 页数超过限制。

拆分 PDF 或调整配置。
415UNSUPPORTED_FILE_TYPE

文件头不是支持的 PDF 或图片格式。

转换文件格式后重试。
422INVALID_ARGUMENT

DPI、输出格式、引擎或 OCR 组合无效。

按参数表修正请求。
422PDF_RENDER_FAILED

PDF 损坏、加密或无法渲染。

检查或重新生成 PDF。
422OCR_FAILED

某一页 OCR 执行失败。

检查文件并保留 request_id。
503ENGINE_UNAVAILABLE

解析引擎或异步队列不可用。

检查 /health，稍后有限重试。
500INTERNAL_ERROR

未预期的服务端异常。

记录 request_id 并联系维护方。
