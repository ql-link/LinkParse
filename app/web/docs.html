CONVENTIONS

通用请求约定

所有接口使用当前站点作为 Base URL。解析接口上传文件，管理接口提交 JSON，响应最外层始终为 JSON。

认证AuthorizationBearer <TOKEN>

注册、登录和公开接口无需 Token；账户接口必须使用登录会话，解析接口可使用会话或用户 API Key。

请求追踪X-Request-IDdemo-request-001

可选，允许字母、数字及 ._:-，最长 128 字符；响应头会原样返回。

文件上传Content-Typemultipart/form-data

由 HTTP 客户端自动生成 boundary，不要手工固定该请求头。

JSON 配置Content-Typeapplication/json

仅 PUT /v1/admin/config 使用。

默认文件上限50 MB
默认 PDF 页数50 页
页级 OCR DPI280
最低 OCR 置信度0.8
默认结果保留24 小时
安全提示

API Key 不应放入 URL、前端源码或业务日志。生产调用建议主动传入唯一的 X-Request-ID 便于端到端排查。

OUTPUT FORMATS

output_formats 返回格式

参数值是逗号分隔字符串，可选择一种或多种格式。选择格式不会改变 HTTP Content-Type；结果始终放在 JSON 响应的 outputs 对象内。

响应字段outputs.markdown
{
  "outputs": {
    "markdown": "# 项目方案\n\n正文内容……"
  }
}
值字段类型说明
textstring

由最终 Markdown 转换的纯文本，保持 PDF 页序。

jsonobject

OpenDataLoader 结构化结果；发生页级 OCR 时增加 ocr_fallback_pages。

markdownstring

以 ODL_PAGE 标记分页，OCR 补充位于对应页面内。

htmlstring

OpenDataLoader HTML；OCR 补充按来源页插入。

PDF PIPELINE

opendataloader_ocr 的实际逻辑

PDF 始终先经过 OpenDataLoader，再由页级质量门禁决定哪些页面需要 RapidOCR；客户端不选择互斥引擎。

PNG / JPEG / WebP / TIFFRapidOCR

直接图片输入执行 OCR。

text_pdfOpenDataLoader + 0 页 OCR

结构和文本通过门禁时不做无意义 OCR。

scanned_pdfOpenDataLoader + 全页 OCR

保留页码来源，再渲染所有有内容的扫描页进行 OCR。

mixed_pdfOpenDataLoader + 部分页 OCR

保留整体结构，只补齐门禁识别出的扫描页或丢失文本页。

主结果

OpenDataLoader 原文始终保留。

选择依据

页码、图片覆盖率、文本保留率与有效字符数。

OCR 补齐

RapidOCR 输出追加到对应页面。

最终门禁

补齐后仍不完整或低置信度则明确失败。

AUTH API

注册、登录与会话

密码只保存带随机盐的 scrypt 摘要。登录成功返回 lps_ 会话令牌；生产环境必须通过 HTTPS 传输。

POST/v1/auth/register
无需鉴权 · HTTP 201
请求
{
  "username": "link_user",
  "email": "user@example.com",
  "password": "at-least-8-characters"
}
响应
{
  "access_token": "lps_...",
  "token_type": "bearer",
  "expires_at": "2026-08-09T10:00:00Z",
  "user": { "id": "1", "username": "link_user", "email": "user@example.com" }
}
POST/v1/auth/login
无需鉴权

提交 account（用户名或邮箱）与 password，响应结构与注册相同。GET /v1/auth/me 返回当前用户与统计；POST /v1/auth/logout 撤销当前会话，这两个接口必须使用 lps_ 会话令牌。

ACCOUNT API

API Key 与解析记录

以下接口只接受登录会话，不接受用户 API Key。完整 lpk_ Key 仅在创建响应中出现一次。

方法与路径响应说明
GET /v1/account/keys200

列出当前用户的有效和已撤销 Key，仅返回前缀。

POST /v1/account/keys201

请求体为 {"name":"生产服务"}，最多保留 10 个有效 Key。

DELETE /v1/account/keys/{key_id}204

立即撤销当前用户指定 Key。

GET /v1/account/records200

使用 limit=1..100、offset>=0 分页查询同步与异步解析记录。

POST/v1/parse
Bearer Session / API Key

同步解析文档

上传文件并等待解析完成，成功返回 ParseResponse。适合图片和短 PDF；长文档建议使用异步任务。

请求参数 · multipart/form-data

字段类型 / 默认值说明与示例
file 必填File

PDF、PNG、JPEG、WebP、TIFF。示例：@resume.pdf。

output_formatsCSV string · text,json

text,json,markdown,html 的任意非空组合。

include_bboxboolean · true

是否在 OCR JSON 的每个文字块中返回 bbox；置信度始终返回。

include_imagesboolean · false

设为 true 后把内嵌图片、OCR 页面图或原始图片上传到阿里云 OSS，并返回 assets。

响应字段类型说明
request_idstring

请求追踪 ID，与响应头 X-Request-ID 一致。

filenamestring

经过安全处理后的原文件名。

enginestring

PDF 固定为 opendataloader_ocr；直接图片输入为 rapidocr。

detected_typestring

image、text_pdf、scanned_pdf、mixed_pdf。

outputsobject

只包含 output_formats 请求的格式。

assetsarray

图片资源列表。未开启图片输出时为空数组；kind 为 embedded_image、page_image 或 source_image。

assets[].urlstring

OSS 图片 URL。公共域名模式下地址本身不签名且 expires_at=null；对象仍会随结果保留期限被定时删除。私有桶模式返回有时效的签名地址。

meta.page_countinteger

文档总页数；图片固定为 1。

meta.duration_msinteger

服务端解析耗时，单位毫秒。

meta.pdf.initial_qualityobject

OpenDataLoader 主解析后的逐页质量报告和待 OCR 页。

meta.pdf.final_qualityobject

页级 OCR 合并后的最终门禁结果；成功响应固定为 PASSED。

meta.pdf.ocr_pagesinteger[]

本次实际执行 RapidOCR 的 PDF 页码。

POST/v1/jobs
Bearer Session / API Key · HTTP 202

创建异步解析任务

请求字段与同步解析完全相同。文件入队后立即返回 job_id，Worker 在后台处理。

请求参数

file、output_formats、include_bbox、include_images 的定义与 同步解析一致。

请求 · cURL
curl -X POST /v1/jobs \
  -H "Authorization: Bearer <API_KEY>" \
  -F "file=@large-document.pdf" \
  -F "output_formats=markdown,json" \
  -F "include_bbox=true" \
  -F "include_images=true"
响应 · 202
{
  "job_id": "job_7f4c1f0c8a6e4f85a8c2…",
  "status": "queued",
  "progress": {
    "current_page": 0,
    "total_pages": 0
  },
  "error": null
}
GET/v1/jobs/{job_id}
Bearer Session / API Key

查询任务状态

客户端应使用创建任务返回的 job_id 轮询。建议从 1–2 秒间隔开始并逐步退避。

路径参数类型说明
job_id 必填string

创建任务时返回的 ID，格式为 job_...。

queued

已入队，等待 Worker。

processing

正在解析，进度字段持续更新。

succeeded

成功，可请求结果接口。

failed

失败，查看响应内 error。

expired

任务或结果超过保留期限。

请求
curl -H "Authorization: Bearer <API_KEY>" \
  /v1/jobs/job_7f4c1f0c8a6e4f85a8c2
响应 · 200
{
  "job_id": "job_7f4c1f0c8a6e4f85a8c2…",
  "status": "processing",
  "progress": {
    "current_page": 8,
    "total_pages": 24

ERROR MODEL

错误响应与处理建议

所有服务端业务错误都使用相同结构。调用方应同时记录 HTTP 状态、error.code 和 request_id。

错误响应示例 · 422
{
  "error": {
    "code": "INVALID_ARGUMENT",
    "message": "Invalid output formats: ['xml']",
    "request_id": "demo-request-001"
  }
}
4xx

修正认证、文件或参数后再请求，不应直接重试。

409

任务未完成，继续按退避间隔查询状态。

5xx

可进行有限次数指数退避重试，并保留 request_id。

HTTP错误码触发条件建议
401UNAUTHORIZED

访问令牌缺失或无效。

检查 Authorization 请求头。
403ADMIN_REQUIRED

当前账户没有管理员权限。

由管理员为 users.is_admin 授权。
401SESSION_REQUIRED

账户接口收到的不是有效登录会话。

重新登录后使用 lps_ 会话令牌。
401INVALID_CREDENTIALS

用户名、邮箱或密码错误。

检查输入；连续失败请求会受到限流。
409ACCOUNT_EXISTS

用户名或邮箱已注册。

直接登录或更换账户信息。
409KEY_LIMIT_REACHED

已有 10 个有效 API Key。

撤销不用的 Key 后重试。
429CONCURRENCY_LIMIT_REACHED

对应解析引擎在等待时间内没有可用槽位。

稍后重试，或由管理员调整该引擎并发上限。
404JOB_NOT_FOUND

任务不存在或已被清理。

停止轮询并重新创建任务。
409JOB_NOT_READY

任务状态尚未 succeeded。

继续查询任务状态。
410JOB_RESULT_EXPIRED

结果文件已经过期。

重新提交原文件。
413FILE_TOO_LARGE

上传文件超过大小限制。

压缩、拆分或调整配置。
413PDF_TOO_MANY_PAGES

PDF 页数超过限制。

拆分 PDF 或调整配置。
415UNSUPPORTED_FILE_TYPE

文件头不是支持的 PDF 或图片格式。

转换文件格式后重试。
422INVALID_ARGUMENT

DPI、输出格式、引擎或 OCR 组合无效。

按参数表修正请求。
422PDF_RENDER_FAILED

PDF 损坏、加密或无法渲染。

检查或重新生成 PDF。
422OCR_FAILED

某一页 OCR 执行失败。

检查文件并保留 request_id。
503ENGINE_UNAVAILABLE

解析引擎或异步队列不可用。

检查 /health，稍后有限重试。
503DATABASE_UNAVAILABLE

账户或解析记录无法可靠写入数据库。

使用新的 X-Request-ID 有限重试，并检查数据库健康状态。
500INTERNAL_ERROR

未预期的服务端异常。

记录 request_id 并联系维护方。
